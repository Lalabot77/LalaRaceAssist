## 8a. Build Engine and Verification Levels

This repository is a classic WPF project targeting .NET Framework 4.8. Prefer the installed Visual Studio MSBuild engine for solution builds because it supplies the WPF markup-compilation targets used to generate `InitializeComponent` and XAML control fields.

Locate the executable instead of assuming a Visual Studio edition or installation path. On Windows, use `vswhere.exe` when available, for example:

```powershell
$vswhere = Join-Path ${env:ProgramFiles(x86)} 'Microsoft Visual Studio\Installer\vswhere.exe'
$msbuild = & $vswhere -all -products '*' -find 'MSBuild\**\Bin\amd64\MSBuild.exe' | Select-Object -First 1
if (-not $msbuild) { throw 'Visual Studio MSBuild was not found.' }
& $msbuild LaunchPlugin.sln /t:Rebuild /p:Configuration=Debug '/p:Platform=Any CPU' /v:minimal
```

Use the configuration and platform selected for the task. `dotnet build` invokes the .NET SDK's MSBuild installation; do not treat it as the authoritative result unless it independently runs WPF markup compilation and generates the required code. Classify missing generated members such as `InitializeComponent` as a possible build-tool/target-configuration failure, and report the evidence without claiming a successful compilation.

Every task's verification report must state its status at each level:

1. **Compilation verification:** solution/project and build engine/configuration, with actual warnings and errors.
2. **Automated logic testing:** applicable automated tests run, or state that no test project/tests exist.
3. **Static and integration checks:** checks performed and their scope/results (for example static validation, packaging, or integration boundaries).
4. **Manual SimHub runtime verification:** state verified only when the plugin has actually been loaded and exercised in SimHub; otherwise explicitly state not performed.
